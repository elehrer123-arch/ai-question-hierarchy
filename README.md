# The Big Questions About AI

**Live site:** https://elehrer123-arch.github.io/ai-question-hierarchy/

A navigable map of the landscape of thought around AI: 5 sections, 26 subsections,
125 open questions — each with a short framing of the live debate and curated
source links (285 in total, from papers to notable posts). The ten load-bearing
cruxes are marked ✱ on the questions that carry them.

## How this repository works

The site is built from structured source data — edit the data, not the HTML:

```
data/              Index content, one JSON file per section
  trajectory.json  safety.json  economy.json  power.json  humanity.json
content/
  questions/       One entry per question (front-mattered Markdown)
templates/
  index.html       Index page template
  entry.html       Entry page template
scripts/
  build.py         Builds everything, with validation (requires: pip install markdown)
index.html         Built output (regenerated by CI on every push)
questions/           Built entry pages
```

Entries are Markdown files with front matter (`question`, `slug`, `title`, `status`,
`section`, `scope`, dates, optional `redirect_from`). Each entry belongs to exactly
one index question — its `slug` must equal that question's slug — and renders to
`questions/<slug>/`, linked from the question on the map. Moved URLs are preserved
via `redirect_from` stub pages.

Every push to `main` rebuilds and redeploys the site automatically via
GitHub Actions. To build locally: `python3 scripts/build.py` from the repo root.

## Question identity

Every question carries three identifiers:

- `id` — its display number (e.g. `1.3.1`). **Changes** as the taxonomy evolves.
- `qid` — its permanent internal ID (e.g. `q_agent_task_horizons`). **Never changes.**
- `slug` — its stable URL name (e.g. `agent-task-horizons`), reserved for future
  per-question pages. Changed only with a permanent redirect.

When editing: renumber freely, never touch `qid`, and treat `slug` as public API.

## Editing

- **Add or improve a source:** edit the question's `links` array
  (`t` title, `s` source/author, `y` year, `u` URL).
- **Correct a framing:** edit the question's `n` field.
- **Restructure:** keep `id` numbers consistent with their subsection, and run
  the build locally — validation fails on duplicates, gaps, or malformed links.
